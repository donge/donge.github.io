Spectrum SDK 本体

Spectrum SDK internals

这页补上速查表原本缺失的中间层：NVIDIA Ethernet Switch SDK（SX SDK，内部 sxd_libs）与其内核驱动 sx_core.ko。SAI 之上是 NOS，SAI 之下就是这里。

This page fills the middle layer the cheatsheet was missing: the NVIDIA Ethernet Switch SDK (SX SDK, internally sxd_libs) and its kernel driver sx_core.ko. Above SAI is the NOS; below SAI is this.

user space :  sx_api_*  →  SDK core (logical model)  →  resource_manager  →  access layer
kernel     :  /dev/sxcdev  ←── ioctl / read / write / mmap ──  sx_core.ko
hardware   :  PCIe (BAR / doorbell / DMA / MSI-X)  →  Spectrum ASIC

SDK 分层与职责

SDK layering & responsibilities

用户态 SDK 是分层的：sx_api_* 门面负责校验与版本兼容；SDK 核心维护逻辑模型（端口/VLAN/FDB/路由）并计算表项与依赖；resource_manager 管芯片资源与容量分配；access 层发送命令、接收事件。内核侧只有 sx_core.ko，独占硬件。

The user-space SDK is layered: the sx_api_* facade validates and handles versioning; the SDK core keeps the logical model (ports/VLAN/FDB/routes) and computes entries and dependencies; resource_manager manages chip resources and capacity; the access layer issues commands and receives events. On the kernel side only sx_core.ko exists, owning the hardware.

设计要点：逻辑放用户态（可快速迭代、可重启），硬件访问集中在内核（安全、单一所有者、与内核网络栈集成）。跨层只用对象 ID 与事务，不共享裸指针。

Design point: logic lives in user space (fast iteration, restartable); hardware access is centralized in the kernel (security, single ownership, kernel-network integration). Cross layers exchange object IDs and transactions, never raw pointers.

主机接口 ABI

Host interface ABI

单个字符设备 /dev/sxcdev（major 230）承载全部通信：ioctl 做控制（命令为裸 enum，参数用 copy_from/to_user）；read/write 传报文与事件；mmap 映射驱动分配的共享缓冲，实现零拷贝的计数器与 dump。

A single char device /dev/sxcdev (major 230) carries all communication: ioctl for control (command is a raw enum, arguments via copy_from/to_user); read/write for packets and events; mmap for driver-allocated shared buffers enabling zero-copy counters and dumps.

接口Interface用途Purpose
ioctl能力查询、配置、CR 读写、寄存器访问Capability query, config, CR read/write, register access
read/writetrap 报文上送 / 报文注入Trapped-packet upcall / packet injection
mmap共享缓冲（bulk counter、AF counter、CR dump）Shared buffers (bulk/AF counters, CR dump)

ABI 头 kernel_user.h 内核/用户双编译，字段用定宽类型保证跨 CPU 架构布局稳定；sx-kernel 与 sys-sdk 版本成对锁定。内核是安全边界，所有用户输入视为不可信。

The ABI header kernel_user.h is dual-compiled for kernel and user; fixed-width fields keep the layout stable across CPU architectures, and sx-kernel / sys-sdk versions are paired. The kernel is the security boundary and treats all user input as untrusted.

命令与寄存器通道

Command & register channels

驱动有两条通往固件的通道。命令接口走 BAR0 的 HCR 邮箱：填 TLV、置 GO 位、由 EQ 事件按 token 完成，用于引导（QUERY_FW / MAP_FA）与多数寄存器访问。EMAD 走数据面以太报文（ethertype 8932），按 64-bit TID 匹配回复，用于需要固件侧异步/时延信息的访问。

The driver has two firmware channels. The command interface uses the HCR mailbox in BAR0: fill a TLV, raise the GO bit, complete by an EQ event matched by token — used for boot (QUERY_FW / MAP_FA) and most register access. EMAD uses data-path Ethernet frames (ethertype 8932), matched by a 64-bit TID, for accesses needing firmware-side async/latency information.

寄存器层把两者统一为 sx_ACCESS_REG_* / sx_EMAD_ACCESS_REG_*，由 auto_registers 从规格脚本生成——规格即真相，避免手写字段不一致。

The register layer unifies both as sx_ACCESS_REG_* / sx_EMAD_ACCESS_REG_*, generated by auto_registers from spec scripts — specs are the source of truth, avoiding hand-written field inconsistency.

队列与中断

Queues & interrupts

三级队列：EQ 载事件（CQ 通知或命令完成），CQ 载完成（RX 报文 / TX 完成），DQ 分 SDQ（发送）与 RDQ（接收）描述符环。中断 → tasklet/workqueue → 轮询 CQ 取出 CQE。

Three queue tiers: EQ carries events (CQ notifications or command completions), CQ carries completions (RX packets / TX completions), and DQ splits into SDQ (send) and RDQ (receive) descriptor rings. Interrupt → tasklet/workqueue → poll the CQ to pop CQEs.

每设备多个单线程工作队列（WJH / 内部高 / 内部低 / SDQ / USER），高优先 CQ 直接在 softirq 处理；完成用 owner/generation 位判定新旧；有 budget 与重调度避免独占 CPU。doorbell 与 CR 空间由内核映射，用户态不直接碰 BAR。

Each device has several single-thread workqueues (WJH / internal-high / internal-low / SDQ / USER); high-priority CQs run directly in softirq. Completions use owner/generation bits; budgets and rescheduling avoid monopolizing the CPU. Doorbells and CR space stay kernel-mapped; user space never touches the BAR directly.

trap / syndrome 与 BFD

Traps, syndromes & BFD

控制报文按 syndrome 上送：ASIC trap → RDQ → CQ 轮询 → 匹配已注册的 listener_entry → 用户态 poll()/read()。用户态 SDK 用 ctrl_cmd_add_synd 注册监听。这里的 polling 是中断驱动的 CQ 轮询，不是用户态忙轮询。

Control packets are trapped by syndrome: ASIC trap → RDQ → CQ poll → match a registered listener_entry → user-space poll()/read(). The SDK registers listeners via ctrl_cmd_add_synd. This polling is interrupt-driven CQ polling, not user-space busy polling.

BFD 是例外：需要毫秒级确定性，故由独立内核模块 sx_bfd.ko 处理——自建 UDP socket（3784 单跳 / 4784 多跳）、内核 delayed_work 定时器、/dev/bfdcdev 控制接口。普通协议逻辑与定时在用户态，容忍秒级。

BFD is the exception: it needs millisecond determinism, so a separate kernel module sx_bfd.ko handles it — its own UDP sockets (3784 single-hop / 4784 multihop), kernel delayed_work timers, and the /dev/bfdcdev control interface. Ordinary protocols keep logic and timers in user space, tolerating seconds.

设计模式与代际

Design patterns & generations

三种间接解耦：dev_specific_cb（按 PCI ID 选中的芯片 ops 函数表）、sx_interface（卫星模块插件总线：netdev/bfd/spice）、CQ 的 sched/poll 策略回调（同一引擎驱动 TX/RX/monitor）。

Three indirections: dev_specific_cb (per-chip ops table selected by PCI ID), sx_interface (satellite-module plugin bus: netdev/bfd/spice), and CQ sched/poll strategy callbacks (one engine drives TX/RX/monitor).

代际差异由 resource_manager（spectrumN.h、switch_quantum*.h、switch_ib.h）描述，一个内核二进制通吃多代 ASIC。变化点收敛为函数表而非散落 #ifdef；这些 SDK 设计原则可迁移到任何芯片栈。

Generation differences live in resource_manager (spectrumN.h, switch_quantum*.h, switch_ib.h), so one kernel binary serves multiple ASIC generations. Variation points collapse into tables rather than scattered #ifdefs; these SDK principles transfer to any chip stack.
