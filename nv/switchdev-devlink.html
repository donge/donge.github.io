FDB 通知

FDB notifications

硬件学习/老化通过 SWITCHDEV_FDB_ADD_TO_BRIDGE / DEL_TO_BRIDGE 等对应版本接口通知 bridge；内核配置的 FDB 通过 TO_DEVICE 路径下发。

Hardware learning/aging uses version-appropriate bridge-directed notifications, while configured FDB state follows device-directed paths.

接口命名随内核演进，应核对目标头文件；核心是区分事件方向与外部学习标志。

Names evolve across kernels: check target headers. Event direction and externally learned flags are the essential distinction.

TC flower 卸载

TC flower offload

Flower 用 key/mask 描述字段，action 可包括 drop、redirect、police 等。

Flower represents fields as keys/masks with actions such as drop, redirect or police.

skip_sw 要求避免软件执行，skip_hw 禁止硬件卸载；in_hw 与硬件 counter 提供卸载证据，但动作组合和 stats 更新周期仍依驱动。

skip_sw avoids software execution; skip_hw prevents hardware offload. in_hw and hardware counters provide evidence, while action combinations and update cadence remain driver-specific.

Devlink 对象

Devlink objects

devlink port 映射物理/逻辑端口，resource 显示设备资源，trap/trap group/policer 描述上送，health reporter 提供诊断和恢复。

Devlink ports represent physical/logical ports; resources expose device capacity; traps/groups/policers describe punts; health reporters diagnose/recover.

reload 可涉及 driver reinit 或 firmware activate，但并非每个设备支持全部动作。

Reload may support driver reinitialization or firmware activation, but support varies.

Representor / e-switch

Representor / e-switch

Representor 是虚拟端口的 Linux 控制/观测接口，实际 VF-to-VF 数据可由 NIC e-switch 硬件转发。

Representors expose virtual ports for Linux control/observation while NIC e-switches may forward VF traffic in hardware.

DPDK 绕过内核数据路径与 switchdev 控制 ASIC 是不同机制，不能把所有高速路径统称为“内核卸载”。

DPDK bypass and switchdev control are distinct mechanisms, not one generic kernel offload path.

三个不同观察面

Three observation planes

Linux bridge/FIB 表示内核控制态，devlink 表示设备级能力/健康，ASIC 表表示硬件实际对象。为一次 VLAN/FDB 更新记录这三个面的时间线。命令成功只证明对应接口接受了操作；是否硬件卸载要结合 offload 标志、驱动反馈与硬件数据面证据。

Linux bridge/FIB represents kernel control state, devlink device capability/health, and ASIC tables actual objects. Trace all three during a VLAN/FDB update. Command success proves interface acceptance; hardware offload additionally needs flags, driver feedback and data-plane evidence.
