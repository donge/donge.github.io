分层定位

Layered localization

业务/collective → GPU/NIC → 链路 → 队列/转发 → 控制面 → SDK/ASIC；先确定范围、起点和最近变更，再逐层证伪。

Application/collective → GPU/NIC → link → queues/forwarding → control plane → SDK/ASIC. Establish scope, onset and recent changes, then test hypotheses layer by layer.

从“何时开始、影响哪些端点、哪些未受影响、最近变化是什么”缩小范围。选一条正常路径与异常路径比较相同指标；先保留现场再变更配置，避免恢复动作抹掉根因证据。

Narrow scope through onset, affected/unaffected endpoints and recent changes. Compare the same metrics on healthy and failing paths. Preserve evidence before configuration changes so recovery does not erase the root cause.

数据面证据

Data-plane evidence

Port packets/octets、CRC/FEC、drop reason、queue watermark/occupancy、ECN/PFC、ACL hit、镜像/采样和硬件表 dump。

Port packets/octets, CRC/FEC, drop reasons, queue watermarks/occupancy, ECN/PFC, ACL hits, mirrors/samples and hardware table dumps.

计数器差分必须使用相同时间窗，并注明取样位置和是否包含镜像/复制。Ingress 与 egress 不相等可能是合法复制或丢弃；先按报文类别建立守恒关系，再用 drop reason 找失配位置。

Counter deltas need aligned windows and documented sampling points, including mirrors/replication. Ingress/egress differences may be legitimate replication or drops. Establish per-class accounting, then use drop reasons to locate discrepancies.

控制面与关联

Control plane & correlation

RIB/FIB/邻居、事件积压、API latency/failure、CPU/内存、对象数；关联 timestamp/request/OID/端口/版本，保留故障前窗口。

RIB/FIB/neighbors, event backlog, API latency/failures, CPU/memory and object counts. Correlate timestamps, request/OIDs, ports and versions; retain pre-failure history.

每次配置请求携带关联标识，日志记录对象业务键、代际、阶段与结果。跨设备时钟不一致会制造错误因果顺序；无法严格同步时同时记录单机单调时间与已知误差范围。

Attach correlation IDs to configuration requests and log semantic keys, generations, stages and outcomes. Unsynchronized devices can create false causal ordering. Record local monotonic timing and known clock uncertainty when strict synchronization is unavailable.

遥测陷阱

Telemetry pitfalls

Counter/gauge/histogram、streaming、sFlow/INT；注意采样、重置/溢出、基数与时间同步。低平均利用率≠无突发，ping 正常≠RDMA 正常。

Counters/gauges/histograms, streaming, sFlow/INT; account for sampling, resets/wraps, cardinality and clock synchronization. Low average utilization does not exclude bursts; ping does not validate RDMA.

Watermark 反映一段时间的峰值，瞬时 occupancy 可能错过微突发；采样平均值又可能被平滑。明确清零策略与时间范围，并将高频队列观测与端口丢包/ECN/PFC 联合解释。

Watermarks capture interval peaks while instantaneous occupancy can miss microbursts and averages can smooth them away. Define reset policy and time scope, then interpret high-frequency queue observations with drops, ECN and PFC.

观测事件结构

Observation event schema

事件至少带设备/端口稳定标识、业务对象键、generation、阶段、时间戳、时钟类型、结果和错误码。指标采用低基数维度；把每个 flow_id 作为长期 metric label 会造成基数爆炸，细粒度对象更适合有限保留的 trace 或结构日志。

Include stable device/port ID, semantic key, generation, stage, timestamp/clock type, result and error code. Keep metric dimensions low-cardinality; long-lived labels per flow can explode cardinality. Detailed objects fit bounded traces/structured logs better.

算例：计数差分

Example: counter deltas

10 秒窗口入口 1,000,000 包、出口 990,000 包不立即等于丢了 10,000：检查窗口边界、队列残留、复制、trap、不同统计口径与 counter reset。先将入/出/丢弃/上送统一到同一测量域，再进行守恒分析；多播场景出口总包数合法地大于入口。

1,000,000 ingress and 990,000 egress packets over 10s does not immediately prove 10,000 losses. Check boundaries, queued packets, replication, traps, semantics and resets. Align ingress/egress/drop/punt domains before conservation analysis; multicast can legitimately produce more egress packets.

时序与根因

Timeline & causality

把 queue watermark 上升、ECN 标记、PFC、NIC retry 与应用延迟放到同一时间线，但说明各采样窗口与时钟误差。相关性不能单独证明因果；用受控负载或单变量变更验证假设。观测工具若改变 CPU/时序，应记录启用前后的基线差异。

Correlate watermarks, ECN, PFC, retries and application latency while stating sampling windows/clock error. Correlation alone does not prove causality; use controlled loads or single-variable changes. Record baseline perturbation if instrumentation changes CPU/timing.
