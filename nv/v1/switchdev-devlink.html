switchdev [S1]

switchdev [S1]

将内核控制的转发平面卸载到硬件；关注 bridge/FDB/VLAN/FIB 同步、offload 失败、学习/老化事件以及重复转发。

Offloads kernel-controlled forwarding to hardware. Check bridge/FDB/VLAN/FIB synchronization, offload failures, learning/aging events and duplicate forwarding.

内核与硬件可能都产生 FDB 学习事件；需指定学习所有者和回传方式，避免事件回环。验证删除/移动与硬件通知并发时最终一致，同时检查 unsupported 操作的错误能否回到调用者。

Both kernel and hardware may produce FDB learning events. Define ownership and feedback to avoid event loops. Test convergence when deletes/moves race with hardware notifications, and ensure unsupported-operation errors reach callers.

devlink [S2]

devlink [S2]

设备/ASIC 级管理：资源、参数、端口、health、traps、reload；各驱动支持范围不同，查询能力后再设计依赖。

Device/ASIC-level management: resources, parameters, ports, health, traps and reload. Support varies by driver; query capabilities before depending on features.

Health reporter 应同时提供可诊断状态和受控恢复动作；自动 reset 可能暂时清除现场。先收集 dump、最近命令、资源与固件状态，再按策略恢复，并记录恢复次数以识别反复失败。

Health reporters should expose diagnostic state and controlled recovery. Automatic resets can erase evidence. Collect dumps, recent commands, resources and firmware state before recovery, and count recoveries to detect recurring faults.

TC / BPF

TC / BPF

tc flower match/action、硬件统计、skip_sw/skip_hw；eBPF/XDP 主机快路径与观测不等于 ASIC 可卸载，需验证动作组合与 fallback。

tc flower matches/actions, hardware statistics and skip_sw/skip_hw. Host eBPF/XDP acceleration or observability does not imply ASIC offload; verify action combinations and fallback.

规则在软件可表示不意味着硬件能执行：匹配字段、动作顺序和计数精度都可能受限。用“仅硬件”要求验证 offload 是否真的成功，并比较硬件统计与端口流量；不能仅以规则创建成功判断。

Software-expressible rules may exceed hardware limits on fields, action order or counter precision. Use hardware-only requirements to verify actual offload and compare hardware statistics with port traffic. Rule creation alone is insufficient evidence.

相邻机制

Related mechanisms

DSA、representor、SR-IOV/e-switch、vDPA、DPDK/AF_XDP 各有场景；检查 reset、锁、资源回收、extack 和内核/固件兼容。

DSA, representors, SR-IOV/e-switch, vDPA and DPDK/AF_XDP serve different uses. Check resets, locking, cleanup, extack and kernel/firmware compatibility.

Representor 是管理/控制某个虚拟端口的 Linux 接口，不代表全部数据必然经过它的软件路径。评估 SR-IOV/e-switch 时区分虚拟功能隔离、控制接口与实际硬件转发，不直接套用机架交换机模型。

A representor is a Linux interface for managing/controlling a virtual port; not all data necessarily traverses its software path. Separate VF isolation, control interfaces and hardware forwarding when evaluating SR-IOV/e-switch designs.

三个不同观察面

Three observation planes

Linux bridge/FIB 表示内核控制态，devlink 表示设备级能力/健康，ASIC 表表示硬件实际对象。为一次 VLAN/FDB 更新记录这三个面的时间线。命令成功只证明对应接口接受了操作；是否硬件卸载要结合 offload 标志、驱动反馈与硬件数据面证据。

Linux bridge/FIB represents kernel control state, devlink device capability/health, and ASIC tables actual objects. Trace all three during a VLAN/FDB update. Command success proves interface acceptance; hardware offload additionally needs flags, driver feedback and data-plane evidence.

实验：硬件与软件分叉

Lab: hardware/software divergence

建立受控 bridge/VLAN 和已知单播流，确认硬件计数增长；再注入不受支持动作，观察明确失败还是 fallback。删除规则后确认硬件命中停止、资源释放；驱动 reset 后确认 bridge/FDB 能重新同步。实验只在隔离测试设备进行，具体创建命令依据驱动和内核版本。

Establish a controlled bridge/VLAN and known-unicast flow, verify hardware counts, then introduce an unsupported action and observe rejection versus fallback. After deletion require hits to stop and resources to release; after reset require resynchronization. Use isolated test devices and version-specific commands.

可靠性不变量

Reliability invariants

一个学习事件不能在硬件→内核→硬件之间无限回环；删除后晚到的旧学习事件不能恢复已失效位置；offload 不支持时必须有可诊断信息。必要时以端口 epoch 和事件来源区分旧通知，设计全量校准而非仅依赖“通知绝不丢”。

Learning must not loop indefinitely hardware→kernel→hardware; late stale events must not restore invalid locations; unsupported offload needs actionable feedback. Use port epochs/event origins where appropriate and provide full reconciliation instead of assuming lossless notifications.
