交换与路由

Switching & routing

ASIC 专用集成电路；SDK 软件开发套件；NOS 网络操作系统；SAI 交换抽象接口；FDB 转发表；RIB 路由信息库；FIB 转发信息库；TCAM 三态内容寻址存储。

ASIC: application-specific integrated circuit; SDK: software development kit; NOS: network operating system; SAI: switch abstraction interface; FDB: forwarding database; RIB: routing information base; FIB: forwarding information base; TCAM: ternary content-addressable memory.

FDB 按 MAC/广播域定位二层出口，RIB 保存路由候选与选择，FIB 为转发使用；ASIC 中又有实际硬件编码。排障时明确正在读哪一层，不把这些表的名字当成等价概念。

FDBs locate L2 egress by MAC/broadcast domain; RIBs hold route candidates/selection; FIBs serve forwarding, with further hardware encoding in the ASIC. Identify the layer being inspected rather than treating these tables as synonyms.

Fabric 与拥塞

Fabric & congestion

VRF 路由实例；VNI VXLAN 网络标识；VTEP 隧道端点；BUM 广播/未知单播/多播；ECMP 等价多路径；PFC 优先级流控；ECN 显式拥塞通知；CNP 拥塞通知包。

VRF: virtual routing and forwarding; VNI: VXLAN network identifier; VTEP: VXLAN tunnel endpoint; BUM: broadcast, unknown unicast, multicast; ECMP: equal-cost multipath; PFC: priority flow control; ECN: explicit congestion notification; CNP: congestion notification packet.

VLAN、VNI 与 VRF 分别属于不同隔离/映射维度，数值相同不意味着同一对象。PFC 作用于链路优先级，ECN 标记报文、由端点反馈；二者都与拥塞相关，但作用范围和控制回路不同。

VLANs, VNIs and VRFs are distinct isolation/mapping dimensions; equal numeric IDs do not imply the same object. PFC affects link priorities; ECN marks packets for endpoint feedback. Both concern congestion but differ in scope and control loops.

系统与 RDMA

Systems & RDMA

DMA 直接内存访问；NUMA 非一致内存访问；RCU 读复制更新；QP 队列对；CQ 完成队列；MR 内存区域；MTU 最大传输单元；BDP 带宽时延积。

DMA: direct memory access; NUMA: non-uniform memory access; RCU: read-copy-update; QP: queue pair; CQ: completion queue; MR: memory region; MTU: maximum transmission unit; BDP: bandwidth-delay product.

NUMA 是 CPU/内存拓扑属性，DMA 是设备访问内存机制，RDMA 是跨端点内存访问能力，三者不能混用。QP/CQ 是传输与完成对象，交换机队列则属于网络流量管理，两种队列也不是同一层。

NUMA describes CPU/memory topology, DMA device memory access, and RDMA remote-endpoint memory access. QPs/CQs are transport/completion objects; switch queues belong to traffic management. These are distinct layers despite shared terminology.

边界检查

Boundary checks

PFC 流控≠ECN 标记；API 返回≠一定硬件生效；进程 HA≠转发不中断；IP 带宽≠应用带宽；可编程≠无限资源。每项追问状态、路径、上限、失败、观测与恢复。

PFC flow control ≠ ECN marking; API return ≠ guaranteed hardware completion; process HA ≠ uninterrupted forwarding; IP bandwidth ≠ application bandwidth; programmable ≠ unlimited resources. Check state, paths, limits, failures, observability and recovery.

使用统一检查表：输入是什么、状态由谁持有、执行路径是什么、哪些资源共享、失败如何报告、结果如何验证、重启如何恢复。对每项功能给出可观测证据，避免以组件名称或 API 名称代替实现理解。

Apply one checklist: inputs, state ownership, execution path, shared resources, failure reporting, result verification and restart recovery. Supply observable evidence for each feature rather than substituting component/API names for implementation understanding.

跨层概念映射

Cross-layer concept map

应用语义：collective、rank、完成；传输语义：QP/CQ、重试、拥塞反馈；网络语义：VRF、下一跳、队列；设备语义：SDK/OID、DMA、固件；OS 语义：skb、NAPI、RCU。先说明问题所在层，再追踪层间关系，避免用一个层的成功状态证明另一个层成功。

Application: collectives/ranks/completion; transport: QP/CQ/retry/congestion; network: VRF/next hops/queues; device: SDK/OID/DMA/firmware; OS: skb/NAPI/RCU. Identify the layer, then trace dependencies. Success at one layer does not prove success at another.

易混实例

Common confusion example

“队列满”可能指 SDK 命令队列、NIC WQ/CQ、Linux qdisc、ASIC buffer 或软件事件队列；它们的生产者、消费者、单位和恢复动作都不同。诊断输出必须写清 queue type、owner、capacity unit、drop/backpressure 行为；否则调整某个 queue depth 很可能作用在错误层。

A full queue may mean SDK commands, NIC WQ/CQ, Linux qdisc, ASIC buffering or software events. Producers, consumers, units and recovery differ. Report type, owner, capacity units and drop/backpressure behavior before tuning a potentially unrelated depth.

技术深度自检

Technical depth check

对任一名词画出输入、状态、输出和失败路径，再给一个具体对象和报文走读。例如 VRF 不只解释为“隔离”，还要说明路由表选择、重叠地址、邻接归属、隧道映射和硬件资源；每项都应能找到可观察状态与可执行验证。

For any term, map inputs, state, outputs and failure paths, then walk an actual object/packet. VRF is more than isolation: explain table selection, overlapping addresses, adjacency ownership, tunnel mappings and hardware resources, each with observable state and executable validation.
