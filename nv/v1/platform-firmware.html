启动与接口

Boot & interfaces

ROM/bootloader → kernel/rootfs → driver → firmware/SDK → NOS；PCIe/BAR/MSI-X、DMA/IOMMU、I2C/MDIO/SPI、CPLD/FPGA/BMC。

ROM/bootloader → kernel/rootfs → driver → firmware/SDK → NOS. PCIe/BAR/MSI-X, DMA/IOMMU, I2C/MDIO/SPI and CPLD/FPGA/BMC.

建立复位域图：复位 CPU、PCIe function、固件或 ASIC 会清除哪些状态？主机可重启不代表交换转发一定保持。初始化顺序应遵守供电、时钟、设备发现、固件就绪和端口配置依赖。

Map reset domains: which state is lost after CPU, PCIe-function, firmware or ASIC reset? A host restart does not imply retained forwarding. Respect power, clocks, discovery, firmware readiness and port-configuration dependencies.

平台管理

Platform management

风扇、PSU、温度/电压、EEPROM、光模块与热插拔；明确驱动/daemon/NOS 边界，设计温控、降频、关机与带外诊断。

Fans, PSUs, temperature/voltage, EEPROMs, optics and hot-plug. Define driver/daemon/NOS boundaries; design thermal control, throttling, shutdown and out-of-band diagnostics.

传感器异常需要区分真实过热、读失败与过期值。热管理采用滞回和持续时间，避免风扇/降频反复震荡；记录温度、风扇转速、端口速率和吞吐时间线，识别热导致的性能退化。

Distinguish genuine overheating from sensor-read failures and stale values. Use hysteresis and duration thresholds to avoid fan/throttle oscillation. Correlate temperature, fan speed, port speed and throughput to identify thermal degradation.

固件合约

Firmware contracts

Mailbox/command queue、ABI/版本、超时/重试、异步事件、reset 域、资源重建和 crash dump；维护驱动/固件/SDK 兼容矩阵。

Mailboxes/command queues, ABI/versioning, timeout/retry, asynchronous events, reset domains, resource reconstruction and crash dumps. Maintain driver/firmware/SDK compatibility matrices.

异步命令应带请求标识和超时状态。超时不能自动解释为设备未执行；reset 后旧 completion 也可能到达，需用 epoch/generation 拒绝过期结果，并规定支持的固件/驱动组合。

Asynchronous commands need request IDs and timeout state. Timeout does not prove non-execution. Stale completions may arrive after reset; reject them using epochs/generations and define supported firmware/driver combinations.

首片验证

Bring-up checks

仿真/emulation → 首片 → 板卡 → 系统；先最小收发/环回，再链路/FEC、查表、流量和热/电源；记录黄金配置、限制与勘误绕过。

Simulation/emulation → first silicon → board → system. Start with minimal TX/RX and loopback, then links/FEC, tables, traffic and thermal/power checks. Record golden configurations, limits and errata workarounds.

Bring-up 每一步只引入一个主要变量：先环回确认收发，再接真实模块，随后开启路由/ACL/QoS。故障出现时保留寄存器、计数器和版本快照；用已知良好的端口/模块交换定位硬件或软件因素。

Introduce one main variable per bring-up step: loopback, then real optics, then routing/ACL/QoS. Preserve register, counter and version snapshots on failure. Swap known-good ports/modules to separate hardware from software causes.

复位域与依赖矩阵

Reset-domain dependency matrix

表格行列列出 CPU、PCIe function、firmware、ASIC core、SerDes 与模块，逐项记录某种 reset 会影响哪些域、哪些表保留、DMA 是否停止、端口是否 flap。所有恢复设计必须以实测 reset 行为为基础；“软重启”名称无法推出故障范围。

Matrix CPU, PCIe function, firmware, ASIC core, SerDes and modules against resets; record affected domains, retained tables, stopped DMA and port flaps. Base recovery on measured reset behavior, not names such as soft reboot.

Bring-up 最小闭环

Minimal bring-up loop

先确认供电/时钟和设备枚举，再读取版本与稳定寄存器；配置一个端口，建立最小 loopback，收发固定模式并检查错误计数；随后加入真实链路和单条转发规则。每一步成功才增加特性，建立可重放的黄金配置而不是依赖工程师手工临时修改。

Verify power/clocks/enumeration, read versions/stable registers, configure one port, establish minimal loopback, send fixed patterns and inspect errors, then add a real link and one forwarding rule. Add features only after each step passes and keep a reproducible golden configuration.

温控案例

Thermal case

如果吞吐随运行时间下降，关联温度、风扇、功耗、CPU/芯片频率和链路状态。传感器值停滞可能是读取失败而非温度恒定；降频阈值应有滞回与安全回退。比较冷启动与恒温稳态结果，避免将热条件差异误当软件版本回归。

For throughput declining over time, correlate temperature, fans, power, CPU/chip frequency and links. Stale sensors can mimic constant temperature. Use hysteresis and safe fallback for throttling. Compare cold and thermally stable runs to avoid misclassifying thermal variation as a software regression.
