端口 up / 路由有但不通

Link up / route present, no traffic

查 VLAN/PVID、LAG/MTU、FEC、FDB/邻居、递归下一跳、ASIC 编程/资源、VRF/隧道和 ACL；对照入出口计数与软硬表。

Check VLAN/PVID, LAG/MTU, FEC, FDB/neighbors, recursive next hops, ASIC programming/resources, VRF/tunnels and ACLs; compare ingress/egress counters and software/hardware tables.

用已知五元组发送少量可识别报文，沿入口、ACL、路由、下一跳、出口逐跳比较计数。对 overlay 同时追踪内外层地址；若控制态正确而硬件表缺失，转向编程错误和资源耗尽排查。

Send a small identifiable flow and compare counters across ingress, ACL, route, next hop and egress. Track inner/outer addresses for overlays. If control state is correct but hardware entries are absent, investigate programming failures and exhaustion.

性能退化 / PFC 风暴

Slow traffic / PFC storms

查微突发、hash 热点、pause 传播、优先级/队列、ECN/CNP、NIC retry 和 GPU/PCIe；升级前后对齐配置/offload/固件再 A/B 回放。

Check microbursts, hash hotspots, pause propagation, priorities/queues, ECN/CNP, NIC retries and GPU/PCIe. Align configuration/offload/firmware before comparing pre/post-upgrade traffic replays.

PFC 风暴应沿暂停传播方向定位最早持续暂停的队列/端点。升级退化先比较默认参数差异、offload 丢失和固件变化；避免一次调整多个 ECN/PFC 阈值，否则难以证明哪项改变有效。

Trace pause propagation to the earliest persistently paused queue/endpoint. For upgrade regressions, compare defaults, lost offloads and firmware changes. Avoid changing multiple ECN/PFC thresholds together or attribution becomes unclear.

UAF / 死锁

UAF / deadlock

收集 core/trace、生命周期、退出/回调竞争与锁图；最小复现后使用 sanitizer/lockdep 验证修复、错误和并发路径。

Collect cores/traces, lifetimes, shutdown/callback races and lock graphs. Build a minimal reproducer, then validate the fix and failure/concurrency paths with sanitizers/lockdep.

UAF 常出现在注销后回调、超时后完成、reset 后旧工作项；死锁常来自回调重入或锁顺序相反。复现应包含重复启动/停止与并发删除，而不是仅验证一次正常收发。

UAF often arises from post-unregister callbacks, late completions or stale reset work; deadlocks often involve reentrancy or reversed lock order. Reproducers should include repeated start/stop and concurrent deletion, not only normal traffic.

表项震荡

State churn

查协议 flap、MAC move、重复/乱序通知、reconcile 互相覆盖、generation 与防抖；比较事件产生/消费速率并定位反馈环。

Check protocol flaps, MAC moves, duplicate/reordered events, competing reconciliation, generations and debouncing. Compare event production/consumption rates and locate feedback loops.

震荡可能由两个模块同时充当状态所有者：一个写配置，另一个根据旧快照回滚。绘制事件因果链，检查每个写入来源、代际与防抖；限速只能缓解负载，不能修复错误的反馈环。

Churn can arise when two modules both own state: one writes configuration, another restores an old snapshot. Trace event causality, writers, generations and debouncing. Rate limiting reduces load but does not fix a faulty feedback loop.

故障树：入口有包出口无包

Fault tree: ingress without egress

先确认统计窗口与报文标识一致；然后按 VLAN/classification→ACL→FDB/FIB→neighbor/rewrite→queue→egress link 分叉。每一步要求一个正向证据和一个排除证据，例如 ACL counter 命中但 drop action 未触发。不要以“配置看着正常”跳过硬件表或资源检查。

Align windows and packet identity, then branch through VLAN/classification→ACL→FDB/FIB→neighbor/rewrite→queue→egress link. Require positive and exclusion evidence at each stage, such as rule hits without a drop action. Do not skip hardware tables/resources because configuration looks correct.

复盘实例：旧完成覆盖新配置

Postmortem: stale completion overwrites intent

g7 创建旧路由、g8 删除该路由，g8 先完成而 g7 completion 晚到；若回调直接写 applied=true，状态库将恢复旧路由。修复应校验 generation/epoch，过期回调只回收自身资源，不覆盖当前目标。回归必须故意反转完成顺序并测试重启恢复，而非仅正常先入先出。

g7 creates a route and g8 deletes it; g8 completes first, then a late g7 callback marks it applied. Validate generation/epoch and let stale callbacks clean only their own resources without overwriting intent. Regression must reverse completion order and include restart, not merely FIFO execution.

如何证明修复

Proving the fix

使用原始复现输入和至少一个相邻边界重跑：并发量、资源接近满、超时/重试或 reset。比较不变量、丢包和资源趋势，并确认没有靠关闭功能规避故障。对于概率竞态，报告迭代次数与覆盖时序，避免把一次未出现描述为完全消除。

Rerun original inputs plus adjacent boundaries such as concurrency, near-capacity, retries or reset. Compare invariants, loss and resource trends; ensure the fix does not merely disable functionality. For probabilistic races, report iterations/orderings rather than treating one clean run as proof.
