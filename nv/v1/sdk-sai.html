抽象边界 [S4]

Abstraction [S4]

SAI 为 forwarding element 提供厂商无关 API；SDK/adapter 落实芯片能力。统一 API 不代表所有芯片资源、原子性与语义相同。

SAI provides vendor-independent APIs for forwarding elements; SDKs/adapters implement chip capabilities. A common API does not imply identical resources, atomicity or semantics.

可移植接口应暴露能力查询和明确的不支持结果；不能用成功返回掩盖软件 fallback。若需要厂商扩展，把扩展限制在适配层并提供能力矩阵，使上层功能可以解释为什么某配置在另一芯片不可用。

Portable interfaces need capability queries and explicit unsupported results; success must not hide software fallback. Confine vendor extensions to adapters and expose capability matrices so upper layers can explain why a configuration is unavailable on another chip.

对象依赖

Object dependencies

Port、VLAN/bridge、router interface、neighbor/next hop、next-hop group、route、ACL table/entry/counter；按 API 依赖建立、逆序释放。

Ports, VLANs/bridges, router interfaces, neighbors/next hops, next-hop groups, routes and ACL tables/entries/counters. Create in API dependency order and release in reverse.

用有向无环图管理引用：route 引用 next-hop group，组引用 next hop，下一跳依赖接口/邻接。共享对象需引用计数；删除某条路由不能顺手删除仍被其他路由引用的组。实际依赖和对象类型以 API 为准。

Model references as a dependency DAG: routes reference groups, groups reference next hops, and next hops depend on interfaces/adjacency. Reference-count shared objects; deleting one route must not remove a group still used elsewhere. Follow the actual API object model.

生命周期与并发

Lifecycle & concurrency

Create/set/get/remove、OID 映射、引用计数、能力查询、create-only 属性、版本兼容；明确线程安全、锁顺序、回调上下文和事件背压。

Create/set/get/remove, OID mapping, references, capability queries, create-only attributes and version compatibility. Define thread safety, lock ordering, callback context and event backpressure.

通知回调通常只做轻量校验和入队，再由工作线程更新状态。需要定义 stop/reset 时是否还能收到回调；注册与注销之间的在途通知必须被排空或安全忽略，否则容易出现 use-after-free。

Keep callbacks lightweight: validate and enqueue, then update state on workers. Define whether notifications can arrive during stop/reset. Drain or safely ignore in-flight callbacks during unregistration to avoid use-after-free.

失败处理

Failure handling

批量 API 未必原子：预校验 → 资源预留 → 依赖排序 → 提交 → 验证；部分失败需补偿/回滚、幂等重试与软硬对账，禁止静默降级。

Bulk APIs may not be atomic: validate → reserve → order dependencies → commit → verify. Partial failures need compensation/rollback, idempotent retry and reconciliation; avoid silent degradation.

假设创建 100 个对象时第 61 个失败：记录每个对象的结果与依赖，区分新建对象和原有共享对象，只补偿本次拥有的资源。重试前先确认超时对象是否已在硬件存在，避免重复分配。

If creation fails at object 61 of 100, retain per-object results and dependencies. Distinguish newly owned resources from existing shared objects and compensate only the former. Before retrying a timeout, determine whether hardware already created the object.

API 合约清单

API contract checklist

对每个 API 定义输入约束、同步返回含义、设备完成条件、线程安全、幂等性、资源归属和可重试错误。OID 是实现标识，恢复时通常还需要业务键定位对象。对 create-only 属性应提前识别“修改实际需要重建”的情况，将重建成本和依赖更新纳入设计，而不是简单 set 失败后循环重试。

Define input constraints, return semantics, device completion, thread safety, idempotency, ownership and retryable errors per API. OIDs are implementation identities; recovery also needs semantic keys. Recognize create-only changes requiring reconstruction and dependent updates instead of repeatedly retrying a failing set.

部分失败的事务日志

Journaling partial failures

日志条目至少包含 operation_id、epoch、object_key、action、previous_state、result。批量创建的结果逐项记录，补偿按依赖逆序执行；共享对象通过引用而非盲目删除回收。若错误返回为资源满，先终止依赖它的新操作；若为 timeout，先查询或 reconcile，防止同一对象重复创建。

Journal operation_id, epoch, object_key, action, previous_state and result. Record bulk outcomes per item and compensate in reverse dependency order. Reclaim shared objects through references. Exhaustion should stop dependent creation; timeouts require querying or reconciliation to prevent duplicate objects.

兼容性测试

Compatibility tests

用同一逻辑测试分别覆盖原生实现、不支持实现和部分支持实现。检查能力查询与实际行为一致、未知属性错误可定位、callback 在 shutdown/reset 后不访问已释放内存。添加不同 API 版本的读取/写入测试，但不要假设旧配置永远可在新版本自动重放。

Run the same logical tests against native, unsupported and partially supported implementations. Check truthful capability reporting, actionable unknown-attribute errors and safe callbacks after shutdown/reset. Test reads/writes across API versions without assuming old configurations always replay unchanged.
