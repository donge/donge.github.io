报文路径

Packet path

MAC → parser → match/classify → L2/L3/ACL → action/rewrite → buffer/MMU → scheduler → egress；实际阶段顺序与动作组合依芯片。

MAC → parser → match/classify → L2/L3/ACL → action/rewrite → buffer/MMU → scheduler → egress. Stage order and action combinations are chip-specific.

Parser 提取字段形成 key；match 选择动作；rewrite 修改报头；流量管理决定缓存与发送。隧道终结可能需要第二次解析或回流，因此新增一个动作也可能消耗额外流水线周期。先走读单包，再检查所有动作组合。

The parser extracts keys, matches select actions, rewrites modify headers, and traffic management buffers/schedules packets. Tunnel termination may require another parse or recirculation pass. Trace one packet, then validate action combinations and their pipeline cost.

查表与资源

Lookup & resources

Exact match、LPM、TCAM、优先级/mask、key width、hash 碰撞；关注 stage 资源、隧道、镜像、复制、计数、drop/trap 的组合限制。

Exact match, LPM, TCAM, priorities/masks, key width and hash collisions. Check stage resources and interactions among tunnels, mirrors, replication, counters and drop/trap actions.

Exact match 适合完整键，LPM 按最长前缀选择，TCAM 支持掩码与优先级。资源估算要计算实际条目宽度、复制和对齐；规则逻辑数量不一定等于物理条目数量，范围匹配还可能展开成多条。

Exact match uses complete keys, LPM selects the longest prefix, and TCAM supports masks and priorities. Budget physical width, replication and alignment. Logical rules need not map one-to-one to entries; range matches may expand into multiple entries.

性能边界

Performance limits

最小帧 pps、recirculation、内部 fabric 与复制带宽可能先饱和；cut-through/store-and-forward、共享缓冲/VOQ 和 HoL 决定时延与拥塞行为。

Minimum-frame pps, recirculation, internal fabric and replication bandwidth can saturate first. Cut-through/store-and-forward, shared buffers/VOQ and HoL shape latency and congestion.

检查瓶颈是否在字节带宽还是包处理次数：大包线速并不能证明小包线速。多播复制和回流放大内部工作量；排队延迟还取决于共享池竞争和出口速度，不能只看无负载的芯片标称延迟。

Separate byte-bandwidth limits from packet-processing limits: large-frame line rate does not prove small-frame line rate. Replication and recirculation amplify internal work. Queue delay depends on pool contention and egress speed, not merely unloaded chip latency.

软件可控性

Software control

寄存器/表访问、DMA 命令、异步完成、影子表、原子更新、资源耗尽、错误码及勘误；P4/可编程 parser 能力按芯片确认。

Register/table access, DMA commands, asynchronous completion, shadow tables, atomic updates, exhaustion, error codes and errata. Verify P4/programmable-parser support per chip.

更新多张表时，设备是否提供原子替换、bank swap 或间接指针切换非常关键。若没有，应通过先建后切再删降低中间态风险，并为失败留下可枚举的恢复信息；不要把“SDK 批量调用”视作硬件事务。

Multi-table updates depend on atomic replacement, bank swaps or indirection support. Otherwise use create-switch-delete sequencing to reduce intermediate-state risk and retain discoverable recovery information. An SDK bulk call is not automatically a hardware transaction.

从逻辑规则到物理布局

From logical rules to physical layout

规则 key 由 parser 输出，stage 只能匹配该时点可用的字段；动作产生的 metadata 往往影响后续 stage。将特性写成“输入字段→查表→动作→输出 metadata”的图，再分配到可用 stage。范围匹配展开、IPv6 宽 key、镜像复制和隧道回流都会改变成本，不能只按 ACL 行数预算。

Keys come from parser outputs; each stage can match only fields available there, while actions may generate metadata for later stages. Map input fields→lookup→action→output metadata before placing features into stages. Range expansion, wide IPv6 keys, mirroring and tunnel recirculation alter cost beyond logical ACL count.

算例：回流吞吐上限

Example: recirculation throughput bound

假设某内部路径可处理 P 次包遍历/s，比例 f 的报文需要额外一次遍历，则平均每个外部包消耗 1+f 次，理想上限约 P/(1+f)。f=1 时该资源对应外部 pps 上限减半。真实 ASIC 可能有独立回流通道或其他先饱和资源，此式只用于识别待验证瓶颈，不能代替芯片规格。

If an internal resource handles P traversals/s and fraction f needs one extra pass, average cost is 1+f and the ideal external bound is P/(1+f). At f=1 that resource permits half the external pps. Dedicated recirculation paths and other bottlenecks may change actual hardware behavior; use this to identify hypotheses, not replace specifications.

验证与常见失败

Validation & common failures

先用单特性流量确认逻辑，再按隧道+ACL+计数器+镜像组合增加。测最小帧、最大帧、多播复制与混合方向；同时检查 stage/表分配失败、CPU trap 激增和 latency 阶跃。若某组合退回软件，功能正确但 pps 大幅下降，应明确判定为能力或性能边界。

Validate features individually, then combine tunnels, ACLs, counters and mirrors. Test minimum/maximum frames, replication and directions while inspecting stage allocation failures, CPU traps and latency steps. A software fallback can preserve function while sharply reducing pps; report the capability/performance boundary explicitly.
