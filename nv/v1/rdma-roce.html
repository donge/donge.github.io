Mechanisms & implementation path

端点对象

Endpoint objects

QP、CQ、WQE/CQE、MR、lkey/rkey；Send/Receive、Read/Write、Atomic；可靠连接的 ACK/NAK、PSN、retry 与完成语义。

QP, CQ, WQE/CQE, MR and lkey/rkey; Send/Receive, Read/Write and Atomic. Understand ACK/NAK, PSN, retries and completion semantics for reliable connections.

MR 注册为访问建立地址/权限与 key，QP 管理传输状态，CQ 返回完成。完成的具体保证取决于操作和协议，不能一概解释为远端应用已消费数据；必须区分网络传输、内存可见性和应用同步。

MR registration establishes memory access and keys, QPs maintain transport state, and CQs report completion. Guarantees depend on operation/protocol; completion does not universally mean remote application consumption. Separate transport completion, memory visibility and application synchronization.

网络封装

Encapsulation

RoCE v1 为 L2；v2 为 UDP/IP，可跨 L3，典型目的端口 4791。交换机通常按网络字段转发，不执行主机 verbs。

RoCE v1 is L2; v2 uses UDP/IP and is routable, typically to UDP port 4791. Switches generally forward on network fields rather than execute host verbs.

RoCE v2 的 UDP/IP 允许路由转发，但不意味着普通 UDP 应用语义；可靠性由 RDMA 传输层处理。检查交换机 hash 是否有足够熵，避免许多大流集中在同一路径，端点配置仍需与 fabric 匹配。

RoCE v2 uses routable UDP/IP but does not have ordinary UDP-application semantics; RDMA transport supplies reliability. Ensure switch hashing has sufficient entropy to avoid concentrating large flows on one path, and align endpoints with the fabric.

拥塞回路 [S8]

Congestion loop [S8]

队列 ECN 标记 → 接收端 CNP → 发送端限速；DCQCN 为相关端点算法。PFC 按优先级暂停链路，映射与阈值需端到端匹配。

Queue ECN marking → receiver CNP → sender rate reduction; DCQCN is a related endpoint algorithm. PFC pauses a link by priority; mappings and thresholds need end-to-end alignment.

在 ECN 触发到发送者真正降速之间仍有在途数据，阈值要结合反馈延迟与瞬时到达速率。CNP 自身也需要及时传递；错误的队列映射或拥塞可延迟反馈，使原有拥塞持续放大。

Data remains in flight between ECN marking and actual sender rate reduction; thresholds must consider feedback delay and instantaneous arrivals. CNP feedback also needs timely delivery. Incorrect queue mapping or congestion can delay it and worsen the original congestion.

部署与排障

Deployment & diagnosis

不把 RoCE 等同于必须全网 PFC；ECN-only/有损方案取决于端点与验证。检查 MTU、DSCP/PCP/TC、PFC/ECN/CNP、buffer drop、retry/QP。

RoCE does not imply mandatory fabric-wide PFC; ECN-only/loss-tolerant designs depend on endpoints and validation. Check MTU, DSCP/PCP/TC, PFC/ECN/CNP, buffer drops, retries and QPs.

按层测试：IP 连通 → RDMA 连通与小规模带宽 → incast/拥塞 → 全集群 collective。若只有多发送者场景失败，重点对比 buffer drop、PFC 持续时间、重试和 CNP，而不是反复用 ping 证明网络正常。

Test IP reachability, then RDMA connectivity/small-scale bandwidth, then incast/congestion and full collectives. If failures appear only with multiple senders, compare buffer drops, PFC duration, retries and CNP rather than repeatedly validating ping.

RoCE 拥塞闭环

RoCE congestion loop

报文在交换机排队并被 ECN 标记，接收端产生 CNP，发送端拥塞算法更新速率，经过传输延迟后出口到达率才下降。分析回路要区分检测时间、反馈时间、算法反应与在途数据；PFC 是局部应急流控，不能自动替代端点拥塞控制。

Queued packets receive ECN marks, receivers generate CNP, sender algorithms adjust rates, and only after transit delay does egress arrival rate fall. Separate detection, feedback, algorithm response and in-flight traffic. PFC is local flow control, not an automatic replacement for endpoint congestion control.

实验：逐级放大 incast

Lab: scaling incast

从 1→1 开始确定主机基线，再增加为 2、4、8 个发送者到同一接收者。固定消息尺寸、持续时间和 NIC 配置，采集 ECN、CNP、PFC 时长、queue watermark、retry 和完成时间。若 1→1 已差，先修端点；只有扩大发送者才差时，重点查拥塞反馈和缓冲。

Establish a 1→1 host baseline, then increase to 2/4/8 senders targeting one receiver. Fix sizes/duration/NIC settings and collect ECN, CNP, pause duration, watermarks, retries and completion times. Poor 1→1 performance points to endpoints; sender-scale failures prioritize congestion/buffering.

关键边界

Critical boundaries

“完成”必须按 verbs 操作语义解释，不能统一当作远端应用已读数据。PFC-free 或有损 RoCE 的可行性取决于 NIC 重传/拥塞能力、负载与 SLA；不能从一种卡和固件的实验结论推广到所有部署。交换机常只处理网络字段，但哈希、队列和重排仍会影响端点效率。

Interpret completions by operation semantics, not universally as remote consumption. PFC-free/loss-tolerant RoCE depends on NIC recovery/congestion behavior, load and SLA; one card/firmware result is not universal. Switches commonly handle network fields, yet hashing, queues and reordering still affect endpoints.
