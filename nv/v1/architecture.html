三平面

Three planes

管理面负责配置、身份、升级和遥测；控制面负责协议与路由计算；数据面负责查表、修改、排队和发送。明确 CPU、ASIC 与固件的职责。

Management handles configuration, identity, upgrades and telemetry; control handles protocols and route computation; data handles lookup, rewrite, queues and transmission. Define CPU, ASIC and firmware ownership.

以新增一条路由为例：管理面接收配置并校验，控制面计算可达下一跳，编排层建立依赖对象，数据面执行查表。控制协议报文可能送 CPU，但普通流量保持 ASIC 转发；设计时分别测管理响应、控制收敛和转发性能。

For a new route, management validates configuration, control resolves reachability, orchestration creates dependencies, and the data plane performs lookups. Protocol packets may reach the CPU while ordinary traffic stays in the ASIC. Measure management response, control convergence and forwarding separately.

控制链

Control path

配置/协议 → 编排 → SAI 或 SDK → ASIC；Linux switchdev 是另一种卸载路径，不是所有系统必经的串联层。

Configuration/protocols → orchestration → SAI or SDK → ASIC. Linux switchdev is another offload path, not a mandatory serial layer in every stack.

将接口画成两类箭头：命令向下、状态与错误向上。每条箭头注明同步/异步、交付保证和超时；例如 SDK 接受请求后，编排层可能仍需等待完成事件。SAI、SDK 和 switchdev 的具体组合由系统实现决定。

Draw downward commands and upward state/error events. Annotate each edge with synchronous/asynchronous behavior, delivery guarantees and deadlines. SDK acceptance may still require a completion event. The system determines how SAI, SDK and switchdev are combined.

一致性

Consistency

区分期望态、软件已应用态与硬件实际态；使用 generation、幂等更新、事件重放、依赖图和 reconcile 处理重复、乱序、漂移与重启。

Separate desired, software-applied and actual hardware state. Use generations, idempotency, replay, dependency graphs and reconciliation for duplicates, reordering, drift and restarts.

为对象保存 desired generation 与 applied generation。若 g=12 的结果在 g=13 后到达，不应覆盖新状态；缺少事件时用全量快照修复。先建立邻接和下一跳，再发布路由；删除时先撤销引用，避免悬空对象。

Track desired and applied generations. A late generation-12 result must not overwrite generation 13. Repair missing events from snapshots. Create adjacency and next hops before publishing routes; remove references before deleting dependencies.

接口与取舍

Contracts & trade-offs

定义状态所有者、API 合约、超时/取消、错误语义、有界队列与背压；权衡可移植性/芯片能力、吞吐/延迟、隔离/利用率。

Define state owners, API contracts, timeout/cancellation, error semantics, bounded queues and backpressure. Trade portability against chip features, throughput against latency, and isolation against utilization.

把超时分成排队、设备执行和确认三段。不可重试错误立即返回；暂时性错误指数退避；结果未知时先查状态再重试。队列达到上限时应拒绝或合并更新，而不是无限占用内存。

Split deadlines into queueing, device execution and acknowledgement. Fail permanent errors immediately; back off transient ones; query state before retrying an unknown outcome. At queue limits, reject or coalesce updates instead of growing memory without bound.

事务状态机

Transaction state machine

将一次更新拆成 RECEIVED→VALIDATED→PREPARED→SUBMITTED→CONFIRMED。SUBMITTED 后超时应进入 UNKNOWN，而不是 FAILED：设备可能已经执行。为每次更新记录业务键、目标代际、依赖集合、旧对象引用与补偿记录。CONFIRMED 必须有已定义的证据，例如完成通知或读回，而不能只看进程间消息已发送。

Model an update as RECEIVED→VALIDATED→PREPARED→SUBMITTED→CONFIRMED. A timeout after submission enters UNKNOWN rather than FAILED: the device may already have applied it. Record semantic key, desired generation, dependencies, old references and compensation data. Confirmation needs defined evidence such as completion notification or readback, not merely a sent IPC message.

完整算例：替换下一跳组

Worked example: replacing a next-hop group

路由 R 原来引用 G1，现在改为 G2。先预留 G2 及成员，确认所有下一跳可用；再将 R 的引用切换到 G2；最后释放 G1 的本次引用。切换失败则保留 G1、回收未共享的 G2；切换结果未知则先查询 R。若硬件不支持原子指针替换，必须明确可能出现的中间态与可接受丢包窗口，不能假设 make-before-break 总能零中断。

Route R references G1 and must move to G2. Reserve G2 and its members, confirm next-hop readiness, switch R to G2, then release this reference to G1. On failure retain G1 and reclaim unshared G2 resources; on unknown outcome query R first. Without atomic pointer replacement, specify intermediate states and acceptable loss windows; make-before-break does not guarantee zero interruption.

故障注入与判定

Fault injection & verdict

分别在建组后、切换前、切换后确认前、旧组删除中杀死进程。重启后期望同一业务键只有一个目标版本，路由不引用不存在的对象，旧组仅在引用数为零时删除。持续流量检查丢包窗口；控制面检查 desired/applied 代际最终一致；资源使用回到基线而不是逐轮增长。

Kill the process after group creation, before switching, after switching but before acknowledgement, and during old-group cleanup. After restart require one target version per semantic key, no dangling route references, and old-group deletion only at zero references. Measure traffic loss, eventual desired/applied convergence and resource return to baseline across repeated cycles.
