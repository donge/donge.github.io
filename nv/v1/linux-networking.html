RX / TX

RX / TX

RX：DMA ring → IRQ/NAPI → skb/GRO → 协议栈/bridge/route；TX：socket/forward → route/neighbor → qdisc → ndo_start_xmit → DMA/completion。

RX: DMA ring → IRQ/NAPI → skb/GRO → stack/bridge/route. TX: socket/forward → route/neighbor → qdisc → ndo_start_xmit → DMA/completion.

NAPI 通过轮询批量处理接收，poll 的 RX 工作受 budget 限制，TX completion 的处理规则不同。驱动需正确协调 IRQ 屏蔽、调度与完成，避免丢失唤醒；budget 增大也可能影响其他任务的延迟。[S11]

NAPI batches receive processing through polling. RX work is budget-limited; TX completion handling follows different rules. Coordinate IRQ masking, scheduling and completion to avoid lost wakeups. Increasing budgets may also affect other tasks' latency. [S11]

核心对象

Core objects

net_device、sk_buff、page/page_pool、socket/netns；skb 线性/非线性、headroom、clone/refcount、GSO/TSO/checksum offload。

net_device, sk_buff, page/page_pool, sockets/netns; linear/nonlinear skb data, headroom, cloning/references, GSO/TSO and checksum offload.

skb 的报头、线性区与 page fragments 可能分开存储，不能假定所有字节连续。Clone 共享底层数据，修改前需满足可写条件；TSO/GSO 大包是主机内表示，抓包看到的大小不一定等于线上帧大小。

skb headers, linear data and page fragments may be separate; do not assume contiguity. Clones share storage, so writes require appropriate ownership. TSO/GSO packets are host representations; captured sizes may differ from wire-frame sizes.

调度与接口

Scheduling & interfaces

softirq、NAPI budget、IRQ affinity、RSS/RPS/XPS、NUMA/cache；rtnetlink/netlink、notifier、ethtool；处理 dump 与通知的竞态和重同步。

softirq, NAPI budget, IRQ affinity, RSS/RPS/XPS, NUMA/cache; rtnetlink/netlink, notifiers and ethtool. Handle dump/notification races and resynchronization.

把 RX 队列、中断、处理 CPU 与内存 NUMA 节点关联起来；跨 NUMA 访问会增加延迟和带宽压力。Netlink dump 与实时通知可能交错，应结合序列/代际和重同步机制建立可靠快照，而非假设一次 dump 永远完整。

Correlate RX queues, interrupts, processing CPUs and memory NUMA nodes; cross-node access adds latency and bandwidth pressure. Netlink dumps can interleave with live notifications. Use sequence/generation handling and resynchronization rather than assuming a single dump is definitive.

卸载边界

Offload boundary

ASIC 数据转发通常不逐包经过 Linux。区分硬件快路径、CPU trap、主机栈与软件 fallback；抓不到包不证明没有转发。

ASIC forwarding typically bypasses Linux per-packet processing. Distinguish hardware fast paths, CPU traps, the host stack and software fallback; an empty capture does not prove no forwarding.

为每类报文画出“硬件转发、trap、copy-to-CPU、软件转发”路径。Trap 和 copy 的含义不同，错误处理可能导致双份报文；诊断 ASIC 路径优先结合硬件计数器、镜像和丢包原因。

Map hardware forwarding, traps, copy-to-CPU and software forwarding for each packet class. Trap and copy semantics differ; incorrect handling can duplicate packets. Diagnose ASIC paths with hardware counters, mirrors and drop reasons.

接收环所有权

Receive-ring ownership

驱动预先提供可 DMA 的缓冲和描述符，设备写入后交付完成信息，CPU 取得所有权再构造或更新 skb。缓冲回收前需确认栈与设备都不再引用。RX ring 太小会在调度延迟期间耗尽，太大可能增加内存与排队；应根据服务间隔和到达包率估算，而不是无限增大。

The driver posts DMA buffers/descriptors; hardware writes data and signals completion; CPU ownership then permits skb construction/update. Recycle only after stack/device references end. Small rings can exhaust during scheduling delays, while large rings increase memory/queueing. Size from arrival pps and service gaps, not unlimited growth.

实验：CPU 饱和但链路未满

Lab: CPU saturation below line rate

固定吞吐逐步减小包长，观察 softirq、每队列包率、NAPI poll 次数和丢包。当字节率相近而 pps 大增时，CPU 可能先饱和。再改变 IRQ affinity/NUMA placement 比较尾延迟与 drops；必须保持 RSS 流分布一致，否则把 hash 偏斜误认为 NUMA 效果。

Reduce packet size at fixed throughput while observing softirq, per-queue pps, NAPI polls and drops. CPU can saturate as pps rises at similar byte rate. Then vary IRQ/NUMA placement while holding RSS distribution fixed to distinguish locality from hash skew.

关键竞态

Critical races

Poll 结束、重新开启中断和设备新完成之间存在时序窗口，驱动必须使用内核要求的调度/完成接口。卸载网络流量不一定经过这些路径，因此先证明被测流走 host path。若仅 CPU trap 流量异常，要检查 trap policer、队列与 CPU，而非直接归咎于 ASIC 普通转发。

Poll completion, interrupt re-enable and new device completions form race windows requiring correct kernel scheduling/completion APIs. Establish that the measured traffic uses the host path: offloaded traffic may bypass it. If only traps fail, inspect trap policers, queues and CPU before blaming ordinary ASIC forwarding.
