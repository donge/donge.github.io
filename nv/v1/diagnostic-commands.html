链路与路由

Links & routes

ip -s link；ip -d link；ip route show table all；ip -6 route；ip neigh；bridge fdb show；bridge vlan show。

ip -s link; ip -d link; ip route show table all; ip -6 route; ip neigh; bridge fdb show; bridge vlan show.

ip -s link 查看统计；ip -d link 查看封装/设备细节；route 查询时带正确 table/VRF。bridge fdb 与硬件 FDB 可能存在同步延迟，因此需用目标 NOS/SDK 的只读查询交叉验证。

ip -s link shows statistics; ip -d link shows device/encapsulation detail. Query routes in the correct table/VRF. Bridge and hardware FDBs may lag each other, so cross-check with read-only NOS/SDK queries.

端口与队列

Ports & queues

ethtool <if>；ethtool -S <if>；ethtool -k <if>；tc -s qdisc show dev <if>；tc -s filter show dev <if> ingress。qdisc 不一定代表硬件队列。

ethtool <if>; ethtool -S <if>; ethtool -k <if>; tc -s qdisc show dev <if>; tc -s filter show dev <if> ingress. qdisc state may not represent hardware queues.

ethtool -S 的计数名与语义由驱动决定，应核实单位、重置条件和聚合范围。tc 的软件统计与硬件统计可能不同步；同一测试窗口内同时采集端口、规则和队列计数。

ethtool -S counter names and semantics are driver-specific: verify units, reset behavior and scope. Software and hardware tc statistics may lag. Collect port, rule and queue counters over the same test window.

设备与系统

Device & system

devlink dev/port/resource/health show（分别执行）；dmesg -T；journalctl -k；ss -s；cat /proc/interrupts；tcpdump -ni <if> -s 0；perf top。

Run devlink dev show, devlink port show, devlink resource show and devlink health show separately; dmesg -T; journalctl -k; ss -s; cat /proc/interrupts; tcpdump -ni <if> -s 0; perf top.

devlink 子系统和 reporter 是否存在依驱动；先发现设备再查询，不把“命令不支持”当作硬件健康。tcpdump/perf 可能需要权限并产生开销，捕获过滤条件应尽量聚焦故障流。

Devlink subsystems/reporters depend on the driver. Discover devices before querying; unsupported commands do not indicate health. tcpdump/perf may require privileges and introduce overhead, so focus captures on relevant traffic.

协议与 RDMA

Protocols & RDMA

vtysh -c "show bgp summary"；rdma link；ibv_devinfo。替换 <if>，核对版本/权限；reload、清计数、reset 与压测会改状态，仅在授权环境执行。

vtysh -c "show bgp summary"; rdma link; ibv_devinfo. Replace <if> and check versions/permissions. Reloads, counter clearing, resets and load tests change state; use authorized environments.

BGP Established 仅证明会话状态，不证明前缀被策略接受或写入 ASIC。ibv_devinfo 展示设备能力也不证明应用 QP 正常；结合路由/硬件表、RDMA 错误及具体应用测试形成闭环。

BGP Established proves session state, not policy acceptance or ASIC programming. ibv_devinfo exposes device capabilities, not application-QP health. Correlate routes/hardware tables, RDMA errors and application tests.

按问题选择命令

Choosing commands by question

“链路是否收帧”先 ip -s link/ethtool -S；“路由是否正确”查询对应 VRF/table；“卸载是否成功”结合 tc/bridge 标志和硬件统计；“设备是否异常”查询 devlink health 与内核日志。不要一次输出所有设备私有寄存器，先用问题限定证据范围。

Use ip -s link/ethtool -S for receive evidence, VRF/table routes for routing, tc/bridge flags plus hardware statistics for offload, and devlink health/kernel logs for device faults. Bound evidence by the question instead of dumping every private register.

只读采集流程

Read-only capture workflow

在 t0/t1 两次采集端口与队列计数，并记录间隔；保存 ip route/neighbor、固件和内核版本、相关日志。保持计数器未清零，读取不可用时标记“不支持/权限不足”而非填零。以稳定端口映射关联 NOS 名称、netdev 和 ASIC logical port。

Collect port/queue counters at t0/t1 with interval, plus route/neighbor state, firmware/kernel versions and relevant logs. Do not clear counters; mark unsupported/permission failures rather than substituting zero. Map NOS names, netdevs and ASIC logical ports through stable identities.

输出解释

Interpreting output

RX dropped 可能来自不同处理阶段，ethtool 私有 counter 必须核对驱动定义；qdisc backlog 描述主机调度，不一定是交换芯片出口队列。BGP Established 与 rdma link ACTIVE 只是局部状态。最终需要报文路径和目标业务验证，否则命令正常也可能有 ASIC 黑洞。

RX dropped semantics vary by stage and private ethtool counters require driver definitions. qdisc backlog is host scheduling, not necessarily switch egress buffering. BGP Established and RDMA ACTIVE are local states. Validate packet paths and the intended workload to exclude ASIC black holes.
