执行与同步

Execution & synchronization

进程/线程、调度、IPC、event loop、workqueue/timer；mutex/spinlock/rwlock、atomic、RCU、completion；锁顺序、优先级反转与中断不可睡眠。

Processes/threads, scheduling, IPC, event loops, workqueues/timers; mutex/spinlock/rwlock, atomics, RCU and completions. Consider lock ordering, priority inversion and non-sleeping interrupt contexts.

Spinlock 适合不能睡眠的短临界区，mutex 允许等待但不能随意用于原子上下文。RCU 将读访问与更新后回收分离：从结构移除对象后仍需等待既有读者结束，才能释放；它不替代所有写侧同步。[S10]

Spinlocks suit short non-sleeping critical sections; mutexes can wait but are not generally usable in atomic contexts. RCU separates reading from reclamation: after removal, wait for pre-existing readers before freeing. It does not replace all writer synchronization. [S10]

内存语义

Memory semantics

虚拟内存、page/slab、栈/堆、碎片/OOM、对齐/字节序；cache coherence 不等于内存顺序；barrier、MMIO、DMA 有独立约束。

Virtual memory, pages/slabs, stack/heap, fragmentation/OOM, alignment/endianness. Cache coherence is not memory ordering; barriers, MMIO and DMA impose distinct constraints.

CPU 可按内存模型重排访问，设备也有自己的可见性规则。写入 descriptor 内容再发布“可用”标志时需合适的顺序保证；coherent DMA 解决一致性的一部分，不自动保证所有发布顺序。[S9]

CPUs may reorder accesses and devices have their own visibility rules. Filling descriptors before publishing availability requires proper ordering. Coherent DMA addresses coherence but does not automatically guarantee every publication order. [S9]

DMA 与生命周期

DMA & lifetimes

Coherent/streaming mapping、IOMMU、cache 同步、ring 所有权；引用计数、延迟释放、取消/回调竞争、UAF/double-free、reset 中未完成 DMA。

Coherent/streaming mappings, IOMMU, cache synchronization and ring ownership. Handle references, deferred frees, cancellation/callback races, UAF/double-free and in-flight DMA during resets.

CPU 虚拟地址、物理地址与设备 DMA 地址不可混用。通过 DMA API 获取设备可见地址，检查映射失败；释放前确保设备停止使用该缓冲。Streaming mapping 的方向和同步必须与数据所有权匹配。[S9]

CPU virtual, physical and device DMA addresses are not interchangeable. Obtain device-visible addresses through DMA APIs and check mapping failures. Stop device use before freeing buffers. Streaming direction and synchronization must match data ownership. [S9]

系统稳定性

System stability

FD/线程/内存泄漏、cgroup、watchdog、磁盘满、时钟跳变；有界队列、背压、重试退避，防止故障放大。

FD/thread/memory leaks, cgroups, watchdogs, full disks and clock jumps. Use bounded queues, backpressure and retry backoff to prevent fault amplification.

泄漏诊断应看趋势而不只看瞬时值：重复配置/删除后资源是否回到基线？重试任务是否积压？故障演练加入磁盘满和时间跳变；使用单调时钟计算持续时间，避免墙上时钟调整破坏超时。

Diagnose leaks by trends: do resources return to baseline after repeated create/delete cycles, and do retries accumulate? Include full disks and clock jumps in fault tests. Use monotonic time for durations so wall-clock adjustments do not corrupt deadlines.

发布与回收是两个问题

Publication and reclamation differ

发布需要读者看到完整初始化对象；回收需要所有旧读者已结束。即使指针赋值是原子的，也不能证明对象字段可见或释放安全。明确采用锁、引用计数或 RCU 的责任：锁保护哪个不变量、引用覆盖哪段异步生命周期、RCU grace period 后才释放哪块内存。

Publication requires readers to see initialized fields; reclamation requires old readers to finish. Atomic pointer assignment proves neither visibility nor safe freeing. Define which invariants locks protect, which asynchronous lifetimes references cover and which memory awaits an RCU grace period.

时序算例：超时后完成

Timeline: completion after timeout

T0 提交请求并持有 context；T1 定时器判超时；T2 调用者释放；T3 设备完成回调访问 context，即 UAF。修复通常需要让设备请求持有独立引用，超时只改变逻辑状态；完成或取消确认后才释放设备引用。还需处理“完成与定时器同时赢”的一次性终态转换。

T0 submit with context; T1 timer expires; T2 caller frees; T3 completion accesses context: UAF. Give the device request an independent reference; timeout changes logical state, and completion/cancel acknowledgement releases device ownership. Resolve simultaneous completion/timer races with a single terminal-state transition.

测试方法

Test method

在请求提交、取消、reset、回调和释放点插入可控延迟，反复运行并发停止/启动。检查 use-after-free、double completion、引用泄漏和锁环。Sanitizer 发现的问题需回到生产路径验证；没有报错不能证明竞态不存在，必须说明覆盖了哪些相对时序。

Insert controlled delays at submit, cancel, reset, callback and free, then repeat concurrent stop/start. Check UAF, double completion, reference leaks and lock cycles. Validate sanitizer findings on production paths; a clean run is not a proof of race freedom—document covered orderings.
