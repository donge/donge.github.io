字节序

Byte order

网络多字节字段使用 big-endian；ntohs/ntohl 与 htons/htonl 在边界转换。

Network multibyte fields use big-endian; convert at boundaries with ntohs/ntohl and counterparts.

IPv4 IHL 以 32bit word 为单位，UDP length 包含 8B UDP 头；不能把协议字段的单位直接当字节偏移。

IPv4 IHL counts 32-bit words; UDP length includes its 8B header. Protocol units are not always byte offsets.

对齐与长度

Alignment & lengths

从不受信任缓冲读结构体可能遇到未对齐和 padding；先验证固定头、变长头再取 payload。

Casting untrusted buffers to structs risks alignment/padding issues.

判断 offset+length≤size 前先避免整数溢出，可改为 offset≤size 且 length≤size−offset。

Validate fixed/variable headers before payload. Avoid overflow in offset+length≤size by checking offset≤size and length≤size−offset.

ABI 与符号

ABI & symbols

结构体大小、字段偏移、调用约定和动态符号共同组成兼容边界。

ABI boundaries include structure sizes/offsets, calling conventions and symbols.

SDK 与头文件版本不匹配可能造成 value union 被错误解释。core 分析要使用对应 build-id 的可执行文件/符号，不是仅同名二进制。

SDK/header mismatch can misinterpret value unions. Decode cores with exact build-ID binaries/symbols, not simply the same executable name.

性能采样解释

Profiling interpretation

perf 的 cycles/instructions/cache-misses 显示不同成本；热点函数可能只是调用汇聚点。

Cycles, instructions and cache misses measure different costs; hot functions may aggregate callees.

火焰图宽度通常对应样本而非调用次数。ftrace 用于时序、KASAN 查内存、KCSAN 查竞争，工具观测层不同。

Flame width usually represents samples, not call count. ftrace exposes timing, KASAN memory faults and KCSAN races at different layers.

边界代码审查样例

Boundary-code review example

解析固件长度字段时先验证最小头长，再检查声明长度≤实际缓冲长度，最后计算偏移；加法/乘法需防溢出，不能先溢出后比较。跨 ABI 的结构不应假定编译器 padding 一致；使用明确字段布局和字节序转换，并验证未知字段/版本的处理。

Validate minimum headers, then declared length≤buffer length, then offsets; guard arithmetic before overflow. Cross-ABI structures must not assume compiler padding. Specify layouts/endianness and test unknown fields/versions.
