RX 典型调用点

Typical RX call sites

驱动 poll 取完成描述符→构造 skb→napi_gro_receive→协议分发→ip_rcv/ipv6_rcv。

Driver poll consumes completions, builds skb and calls napi_gro_receive before protocol dispatch to ip_rcv/ipv6_rcv.

若被转发，可进入 ip_forward；本机流量进入本地交付和传输层。具体函数路径随 GRO、bridge、netfilter 和 offload 改变。

Forwarded IPv4 can enter ip_forward; local traffic reaches local delivery/transport. GRO, bridges, netfilter and offload alter exact paths.

TX 典型调用点

Typical TX call sites

输出路径经路由与邻居解析，再到 dev_queue_xmit/qdisc、驱动 ndo_start_xmit。

Output resolves routes/neighbors, reaches dev_queue_xmit/qdisc and driver ndo_start_xmit.

驱动填 TX ring 并通知设备，完成后回收 DMA 与 skb。qdisc backlog 是主机队列，不是 ASIC 所有出口队列的总和。

The driver posts TX descriptors and notifies hardware, then reclaims DMA/skb after completion. qdisc backlog is host queueing, not total ASIC egress buffering.

sk_buff 内存

sk_buff memory

skb->len 是总长，data_len 描述非线性数据长度，线性头长为 len−data_len；frags 可引用 page 数据。

skb->len is total length, data_len is nonlinear length, and linear head length is len−data_len; fragments can reference pages.

clone 共享数据而复制描述对象。解析器应使用适当 skb 访问/拉入接口，不能无条件从 data 读取全部报文。

Clones share packet storage. Parsers must use suitable skb access/pull helpers rather than assuming all bytes follow data.

NAPI 与 XDP

NAPI & XDP

Native XDP 通常在驱动 RX、构造 skb 之前执行，但取决于驱动支持；generic XDP 路径不同。

Native XDP typically runs in driver RX before skb construction when supported; generic XDP differs.

XDP_PASS/DROP/TX/REDIRECT 分别决定后续处理。NAPI RX budget 与 TX completion 处理规则不同，poll 达到 budget 时不能草率声明完成。

PASS/DROP/TX/REDIRECT choose subsequent processing. NAPI RX budgets differ from TX completion handling; reaching the budget requires appropriate completion behavior.

实验：CPU 饱和但链路未满

Lab: CPU saturation below line rate

固定吞吐逐步减小包长，观察 softirq、每队列包率、NAPI poll 次数和丢包。当字节率相近而 pps 大增时，CPU 可能先饱和。再改变 IRQ affinity/NUMA placement 比较尾延迟与 drops；必须保持 RSS 流分布一致，否则把 hash 偏斜误认为 NUMA 效果。

Reduce packet size at fixed throughput while observing softirq, per-queue pps, NAPI polls and drops. CPU can saturate as pps rises at similar byte rate. Then vary IRQ/NUMA placement while holding RSS distribution fixed to distinguish locality from hash skew.
