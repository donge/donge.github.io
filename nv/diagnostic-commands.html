ip / bridge

ip / bridge

ip -d link 显示设备/封装；ip route show table all 查看多表；ip neigh 显示 NUD；bridge fdb show 显示 MAC/VLAN/port 与 offload 信息。

ip -d link exposes device/encapsulation; route table all shows tables; ip neigh shows NUD; bridge fdb shows MAC/VLAN/port and offload.

不同 namespace/VRF 需进入正确上下文，否则会误读另一张表。

Select correct namespace/VRF or risk inspecting unrelated state.

ethtool / tc

ethtool / tc

ethtool -S 的字段依驱动；-k 显示卸载特性；tc -s qdisc 显示主机调度统计，tc -s filter 查看规则计数。

ethtool -S fields are driver-specific; -k lists offloads; tc -s qdisc shows host scheduling and filters show rule counts.

驱动支持的硬件 stats 可能异步更新，不能要求每次读取与线上包数精确即时相等。

Hardware stats can update asynchronously rather than match wire counts instantaneously.

devlink / 日志

devlink / logs

devlink dev/port/resource/health show 分别执行；journalctl -k 查看内核日志。

Run devlink dev/port/resource/health show separately and inspect kernel logs with journalctl -k.

设备不可见、子命令不支持与 reporter 健康是三种不同结果。reload/clear/reset 会改状态，不属于只读采集。

Missing devices, unsupported commands and reporter health differ. Reload/clear/reset mutates state and is not read-only capture.

FRR / RDMA

FRR / RDMA

vtysh -c "show bgp summary" 看会话；具体前缀需再查 BGP/RIB/FIB。

vtysh show bgp summary reports peers; inspect specific prefixes in BGP/RIB/FIB.

rdma link 与 ibv_devinfo 看链路和设备能力，不表示应用 QP 已正确创建；还需端点错误和实际传输结果。

rdma link/ibv_devinfo exposes links/capabilities, not correctly created application QPs; inspect errors and actual transfers.

按问题选择命令

Choosing commands by question

“链路是否收帧”先 ip -s link/ethtool -S；“路由是否正确”查询对应 VRF/table；“卸载是否成功”结合 tc/bridge 标志和硬件统计；“设备是否异常”查询 devlink health 与内核日志。不要一次输出所有设备私有寄存器，先用问题限定证据范围。

Use ip -s link/ethtool -S for receive evidence, VRF/table routes for routing, tc/bridge flags plus hardware statistics for offload, and devlink health/kernel logs for device faults. Bound evidence by the question instead of dumping every private register.
