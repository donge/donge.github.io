FRR→硬件路由

FRR→hardware routes

FRR bgpd 处理 BGP，zebra 管理路由选择及下发。

FRR bgpd handles BGP; zebra manages route selection and export.

SONiC 参考路径是 zebra→FPM→fpmsyncd→APPL_DB→orchagent→ASIC_DB/syncd→SAI；zebra 到内核的 netlink 更新是并行相关路径，不是 orchagent 直接拦截内核函数。

The SONiC reference path is zebra→FPM→fpmsyncd→APPL_DB→orchagent→ASIC_DB/syncd→SAI. Zebra's netlink updates to the kernel are a related parallel path, not orchagent intercepting kernel functions.

控制报文与 CPU

Control packets & CPU

Trap 将特定报文送 CPU，copy/mirror 可保留原转发并复制。

Trap sends selected packets to the CPU; copy/mirror may retain forwarding while replicating.

BGP 目的为本机时进入主机 TCP 栈；ARP/ND 用于邻居解析；TTL 到期、MTU 异常等可能生成异常处理。上送原因、CPU queue 与 policer 是不同配置对象。

Locally destined BGP reaches the host TCP stack; ARP/ND resolves neighbors; TTL expiry and MTU exceptions may require exception handling. Trap reason, CPU queue and policer are distinct configuration objects.

路由间接寻址

Route indirection

前缀→next-hop group→member→next hop→router interface/neighbor→MAC rewrite。

Prefix→next-hop group→member→next hop→router interface/neighbor→MAC rewrite.

多个前缀可共享同组，成员变化不必逐条改所有前缀；但组数、成员总数和 hash bucket 数可能是不同硬件资源。直接连接路由与 IP2ME 的目标对象也不同。

Prefixes can share a group, allowing member changes without rewriting every prefix. Group count, total members and hash buckets may be separate hardware resources. Connected and IP2ME routes use different target objects.

命令队列与 DMA

Command queues & DMA

MMIO doorbell 通知设备存在新命令；命令内容可通过 DMA 描述符/缓冲传递。

MMIO doorbells notify devices of new commands; DMA descriptors/buffers may carry command payloads.

completion queue 返回完成与状态，interrupt 或 polling 通知软件。并非每次 SDK 操作都是直接 MMIO 写表，更不能推定设备计数器直接 DMA 到 Redis。

Completion queues return status via interrupts or polling. SDK operations are not necessarily direct MMIO table writes, and counters do not universally DMA directly into Redis.

完整算例：替换下一跳组

Worked example: replacing a next-hop group

路由 R 原来引用 G1，现在改为 G2。先预留 G2 及成员，确认所有下一跳可用；再将 R 的引用切换到 G2；最后释放 G1 的本次引用。切换失败则保留 G1、回收未共享的 G2；切换结果未知则先查询 R。若硬件不支持原子指针替换，必须明确可能出现的中间态与可接受丢包窗口，不能假设 make-before-break 总能零中断。

Route R references G1 and must move to G2. Reserve G2 and its members, confirm next-hop readiness, switch R to G2, then release this reference to G1. On failure retain G1 and reclaim unshared G2 resources; on unknown outcome query R first. Without atomic pointer replacement, specify intermediate states and acceptable loss windows; make-before-break does not guarantee zero interruption.
